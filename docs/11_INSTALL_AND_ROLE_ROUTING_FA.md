# طراحی نصب PWA و مسیر‌یابی بر اساس نقش

**تاریخ:** ۸ اکتوبر ۲۰۲۶
**وضعیت:** طراحی پیشنهادی — منتظر تأیید
**مرتبط با:** [`docs/10_VISION_PWA_STRATEGY_FA.md`](./10_VISION_PWA_STRATEGY_FA.md)

---

## اصل اول: هر دو اپ، روی هر دستگاه

```
Nawara Studio — CPM  →  قابل نصب روی موبایل و دسکتاپ
Nawara Tasks         →  قابل نصب روی موبایل و دسکتاپ
```

دستگاه هیچ محدودیتی ایجاد نمی‌کند. تنها چیزی که تعیین می‌کند کجا بروید و چه ببینید، **لاگین شماست**.

---

## اصل دوم: لاگین تعیین می‌کند کجا بروید

| نقش | بعد از لاگین | دسترسی به CPM | دسترسی به Tasks |
|---|---|---|---|
| Head Engineer / Admin | CPM — Dashboard | ✅ | ✅ |
| Project Admin | CPM — Dashboard | ✅ | ✅ |
| Employee / Engineer | **Tasks — «کار من»** | ❌ هدایت به Tasks | ✅ |
| Client (بعداً) | Client Portal | ❌ | ❌ |

### قانون تشخیص: بر اساس permission، نه نام نقش

نام نقش را مبنا قرار نمی‌دهیم (چون بعداً نقش‌ها عوض می‌شوند). به‌جایش:

```
can_use_cpm = کاربر حداقل یکی از این permissionها را دارد
              users.manage  |  settings.manage  |  projects.create
              projects.delete  |  reports.view_all  |  projects.manage_all
```

اگر `can_use_cpm` درست باشد → CPM. در غیر این صورت → Tasks.

یک override دستی هم برای موارد خاص نگه می‌داریم (مثلاً یک انجنیر ارشد که باید گزارش‌ها را ببیند).

### اگر کارمند مستقیم آدرس CPM را باز کند؟

هدایت خودکار به Tasks، با یک پیام کوتاه:

```
حساب شما به بخش تسک‌ها دسترسی دارد.
                                    [ رفتن به Nawara Tasks ]
```

**نکتهٔ امنیتی:** این هدایت فقط ظاهری نیست. همان‌طور که در کل پروژه رعایت کرده‌ایم، **سرور هم باید هر درخواست API مربوط به CPM را برای کارمند با ۴۰۳ رد کند**. مخفی‌کردن لینک کافی نیست.

## اصل سوم: دکمهٔ نصب در بالای هر دو اپ

هر دو اپلیکیشن، در **نوار بالا**، دکمهٔ نصب دارند.

### هدرِ Nawara Studio — CPM

```
┌──────────────────────────────────────────────────────────────────┐
│ Nawara Studio ▾   [⌘K جستجو]        [⬇ نصب ▾] [🔔 ۳] [👤 نام ▾] │
└──────────────────────────────────────────────────────────────────┘
                                          │
                        ┌─────────────────┴─────────────────┐
                        │  ⬇ نصب Nawara Studio روی این دستگاه │
                        │  ✅ Tasks را هم نصب کن      ← جدید │
                        └───────────────────────────────────┘
```

### هدرِ Nawara Tasks

```
┌──────────────────────────────────────────────────────┐
│ ☰ Nawara Tasks   [کار من|برد|تقویم]  [⬇ نصب] [🔔] [👤] │
└──────────────────────────────────────────────────────┘
```

اگر کاربر ادمین باشد، یک لینک کوچک **«باز کردن Nawara Studio»** هم در منوی کاربر دیده می‌شود.

### رفتار دکمه در هر پلتفرم

| پلتفرم | رفتار |
|---|---|
| **Chrome / Edge (Android, Windows, macOS, Linux)** | رویداد `beforeinstallprompt` را می‌گیریم و نگه می‌داریم؛ با کلیک، پنجرهٔ نصب خود مرورگر باز می‌شود |
| **iOS / iPadOS (Safari)** | رویداد نصب وجود ندارد. به‌جایش یک راهنمای تصویری: «Share ← Add to Home Screen» |
| **اپ از قبل نصب شده** | دکمه مخفی می‌شود و به‌جایش نشان «نصب شده ✓» می‌آید |

```js
// منطق کلی — پیاده‌سازی نهایی در مرحلهٔ ۵
let deferredPrompt = null;

window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();          // بنر خودکار مرورگر را نشان نده
  deferredPrompt = e;
  installButton.hidden = false; // دکمهٔ خودمان را در هدر نشان بده
});

installButton.addEventListener('click', async () => {
  if (!deferredPrompt) return showIosGuide();   // iPhone
  deferredPrompt.prompt();
  const { outcome } = await deferredPrompt.userChoice;
  deferredPrompt = null;
  installButton.hidden = true;
});

window.addEventListener('appinstalled', () => {
  installButton.hidden = true;
  showInstalledBadge();
});
```

### یک محدودیت فنی که باید بدانید

مرورگر اجازه نمی‌دهد از داخل یک اپ، نصب اپِ دیگر را فعال کنیم. یعنی:

- دکمهٔ «نصب» داخل CPM → **فقط CPM را نصب می‌کند**
- برای نصب Tasks باید وارد Tasks شوید و آنجا دکمه را بزنید

برای همین در منوی نصبِ CPM گزینهٔ **«Tasks را هم نصب کن»** می‌گذاریم که شما را به `tasks.` می‌برد و همان‌جا راهنما را نشان می‌دهد. دو کلیکِ بیشتر نیست.

## اصل چهارم: یک لاگین برای هر دو

چون دو زیردامنه داریم، session باید بین آن‌ها به اشتراک گذاشته شود:

```
Set-Cookie: nawara_session=...;
            Domain=.nawara.af;
            Secure;
            HttpOnly;
            SameSite=Lax;
            Path=/
```

- `Domain=.nawara.af` → هر دو زیردامنه آن را می‌فرستند
- `Secure` → فقط روی HTTPS (که برای PWA اجباری است)
- `HttpOnly` → JavaScript به آن دسترسی ندارد (ضد XSS)
- `SameSite=Lax` → جابه‌جایی بین زیردامنه‌ها همچنان کار می‌کند

نتیجه: **یک‌بار لاگین می‌کنید، در هر دو اپ وارد هستید.**

خروج از هر کدام، از هر دو خارج می‌کند.

---

## اصل پنجم: نوتیفیکیشن وقتی هر دو نصب باشند

اگر ادمین هر دو اپ را نصب کند، هر کدام اشتراک push جداگانه‌ای دارد. بدون مدیریت، یک اعلان **دوبار** به دستش می‌رسد.

راه‌حل:

```
هر اشتراک push در دیتابیس:  { user_id, app: 'cpm' | 'tasks', endpoint, ... }
هر نوتیفیکیشن:              { notification_id }  ← یکتا
دستگاه: اعلانی که notification_id آن قبلاً دیده شده را نشان نمی‌دهد
```

همچنین تعدادِ خوانده‌نشده (badge) همیشه از سرور خوانده می‌شود، نه از حافظهٔ هر اپ — تا دو اپ عدد متفاوت نشان ندهند.

```json
// app.nawara.af/manifest.webmanifest
{
  "id": "/?source=pwa",
  "name": "Nawara Studio — CPM",
  "short_name": "Nawara CPM",
  "start_url": "/",
  "scope": "/",

  "theme_color": "#0f1419",
```

```json
// tasks.nawara.af/manifest.webmanifest
{
  "id": "/?source=pwa",
  "name": "Nawara Tasks",
  "short_name": "Tasks",
  "start_url": "/",

  "display": "standalone",
```

نکته: `id` جدا و `scope` روی ریشهٔ هر زیردامنه — چون زیردامنه‌ها جدا هستند، دیگر تداخلِ scope نداریم.

## چک‌لیست پذیرش (وقتی پیاده شد، این‌ها را تست می‌کنیم)

### نصب
- [ ] در Chrome دسکتاپ، دکمهٔ نصب در هدر CPM ظاهر می‌شود و نصب موفق است
- [ ] در Chrome اندروید، دکمهٔ نصب در هدر Tasks ظاهر می‌شود و نصب موفق است
- [ ] در iPhone، به‌جای دکمه، راهنمای «Add to Home Screen» نمایش داده می‌شود
- [ ] بعد از نصب، دکمه به «نصب شده ✓» تغییر می‌کند
- [ ] هر دو اپ هم‌زمان روی یک دستگاه نصب می‌شوند و آیکون جدا دارند
- [ ] نصبِ یکی، نصبِ دیگری را خراب نمی‌کند

### مسیر‌یابی نقش
- [ ] لاگین کارمند → مستقیم Tasks باز می‌شود
- [ ] کارمند آدرس CPM را دستی باز کند → هدایت می‌شود
- [ ] کارمند درخواست مستقیم به APIهای CPM بفرستد → **۴۰۳**، نه داده
- [ ] لاگین ادمین → CPM باز می‌شود و لینک Tasks در دسترس است
- [ ] ادمین می‌تواند بین دو اپ جابه‌جا شود بدون لاگین دوباره
- [ ] خروج از یک اپ، از هر دو خارج می‌کند

### امنیت
- [ ] هیچ دادهٔ CPM برای کارمند از طریق API قابل دریافت نیست
- [ ] کوکی session روی مرورگر قابل دسترسی با JavaScript نیست
- [ ] روی HTTP (بدون SSL) هیچ‌کدام نصب نمی‌شوند
