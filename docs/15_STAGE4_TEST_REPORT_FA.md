## ۱. دامنه تأییدشده (برنامه اصلی مرحله ۴)

1. اتصال تسک‌ها به Section/Item — با «تأیید ادمین» درصد ردیفِ item در **جدول موجود** `pm_project_values` به‌روز می‌شود و درصد پروژه خودکار بالا می‌رود.
2. حالت پیشرفت هر پروژه: `manual` (پروژه‌های قدیمی، رفتار قبلی دقیقاً حفظ شده) / `task_driven` (پروژه‌های جدید — پیش‌فرض).
3. Earned Value: قرارداد (مبلغ دستی — بعداً قابل ثبت) → EV، PV، SPI، CPI + پیش‌بینی تاریخ تحویل و انحراف روزانه.
4. S-curve برنامه‌ریزی‌شده در برابر کسب‌شده با اسنپ‌شات روزانه.
5. معیارهای تست برنامه اصلی: پروژه دستی تغییر نمی‌کند؛ task_driven دقیقاً با وزن item بالا می‌رود؛ SPI درست محاسبه می‌شود.

**تأثیر بر نمایش صفحه Projects:** طبق قید ثابت کاربر، نمای فعلی، Edit/Update/New تغییری نکرده — دو فیلد «Progress Engine» و «Contract Value» **داخل فرم موجود** Add/Edit اضافه شد (تأییدیه برنامه اصلی برای همین مرحله). نمای کارت‌ها/لیست دست‌نخورده است.

## ۵. نکات امنیتی و طراحی

- **مهاجرت schema در production بدون تأیید، برنامه را عمداً قفل می‌کند** (گیت `getDB`)؛ ترتیب اجرا: تست روی کپی → بکاپ (گرفته شد: `backups/database.sqlite.bak-stage4-premigration-*` با SHA یکسان) → تأیید صریح کاربر → اعمال با `NAWARA_ALLOW_SCHEMA_MIGRATIONS=1` → راستی‌آزمایی SHA.
- نوشتن پیشرفت فقط از مسیر تراکنشِ تسک؛ حالت‌های manual هرگز توسط موتور تسک لمس نمی‌شوند (N-block).
- EVM روی GET اسنپ‌شات می‌نویسد — ایمن: فقط internal + edit پروژه + نوشتن محدود به یک ردیف روزانه + CSRF روی POST.
- استتار `contract_value` برای بینندگان بدون edit (نشت مالی رفع شد).
- شناسایی‌شده و اصلاح‌شده حین تست: کامای مضاعف SQL در UPDATE دینامیک (فقط فاز توسعه)، انحراف یک‌روزه day_slippage نسبت به نمایش تقویمی، مسدودکردن سِشن ورود کارمند هنگام به‌روزرسانی کاربر (تست باید دوباره login کند — رفتار عمدی `users.php`).

## ۶. تصمیم‌های دامنه

- تغییر status دستی روی آیتمِ لینک‌شده در پروژه task_driven: درصد از تسک می‌آید (task_percent مرجع است)؛ status فقط برای آیتم‌های بدون تسک معیار است — رفتار عمدی حالت.
- مبلغ قرارداد (BAC) و AC همچنان «بعداً»: فیلد در فرم هست، صفر/خالی → معیارهای پولی null.
- نمایش لیست/کارت‌های Projects، Priorities قدیمی، و قراردادهای stage 3 بدون تغییر.
