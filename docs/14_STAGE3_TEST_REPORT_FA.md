## ۲. نتایج تست‌ها (پویش `/tmp/nawara-php/stage3.mjs`)

### راه‌اندازی و انتقال اولویت‌ها (S01–S15) — ۱۵ پاس
- dry-run و اجرای واقعی: «Imported 5 task(s)»؛ اجرای دوم: «0 جدید، 5 ردشده» (idempotent)
- `pm_priorities` دست‌نخورده (۵ ردیف فعال)؛ هر ۵ تسک ورودی «completed» و مهر `priority:<id>` در activity
- ساخت ۴ کاربر آزمایشی (۲ کارمند، اداری، کلاینت) + ورود و دریافت CSRF برای همه

### چرخهٔ کارمند (A01–A20) — ۲۰ پاس — **هستهٔ پذیرش**
- کارمند استارت می‌زند ✅ ولی **تکمیل نهایی تسکِ نیازمند بازبینی = 403** ✅
- ارسال بدون نظرِ اجباری = 422؛ با نظر = موفق؛ `member_status=submitted`
- کارمند روی تسلیم خودش تأیید = 403؛ اداری بدون مجوز بازبینی = 403
- ادمین: درخواست اصلاح (با نظر) ← رزومه توسط کارمند ← ارسال مجدد ← **تأیید = completed**؛ وضعیت عضو = completed
- خروج از completed = 422؛ نسخهٔ قدیمی (stale) = **409**

### بلاک (B01–B07) — ۷ پاس
دلیل نامعتبر = 422، دلیل خالی = 422، دلیل معتبر (از ۶ کد) = ثبت در activity + وضعیت عضو = blocked، رزومه موفق.

### حالت‌های انتساب (C01–C11) — ۱۱ پاس
- **مشترک:** هر عضو می‌تواند ثبت کند؛ استارت، وضعیت *همهٔ* اعضا را in_progress می‌کند؛ ثبت یک نفر = تکمیل ارسال
- **همه باید ثبت کنند:** ثبت نفر اول ← `{partial:true, pending_members:1}` و تسک سر جایش؛ ثبت نفر دوم ← ارسال کامل
- تسک بدون مسئول = draft؛ `assign` آن را assigned می‌کند؛ کاربر ناموجود = 422

### کلید بازبینی (D01–D04) — ۴ پاس
- `review_required=0` ← تکمیل مستقیم کارمند موفق؛
- روشن شدن کلید روی تسکِ در حال اجرا ← تکمیل مستقیم **با 403 رد می‌شود**

### کلاینت (E01–E17) — ۱۷ پاس
- انتشار ← ساخت خودکار ردیف گیرنده با `awaiting_approval`؛
- **کلاینت فقط منتشرشده‌ها را می‌بیند** (لیست فیلتر گیرنده؛ دریافت منتشرنشده = 404 بدون افشای وجود)؛
- نظرات داخلی و تاریخچهٔ داخلی برای کلاینت پنهان؛
- تأیید کلاینت ← completed/approved؛ «درخواست اصلاح» ← revision_requested/changes_requested + نظر client؛
- تصمیم دوم = 422؛ نظر کلاینت بعد از خاموش شدن کلید = 403؛ ایجاد تسک توسط کلاینت = 403

### نظر/چک‌لیست/پیوست (F01–F15) — ۱۵ پاس
عضو پروژه نظر می‌گذارد؛ افزودن آیتم چک‌لیست فقط مدیر، تیک توسط مسئول؛ آپلود تصویر موفق، MIME خارج از فهرست = 422، دانلود کارمند/کلاینت (فقط فایل client-visible با گیرنده و مجوز) صحیح، ناشناس = 401، حذف فقط توسط آپلودکننده/مدیر.

### ماتریس امنیت (G01–G13) — ۱۳ پاس

## ۳. باگ‌های کشف‌و رفع‌شده در همین مرحله (قبل از تحویل)

1. **انتشار به کلاینت همیشه 422 می‌داد** — ردیف گیرنده با `decision=''` نوشته می‌شد که CHECK دیتابیس رد می‌کند ← `'awaiting_approval'` شد.
2. **تصمیم کلاینت هرگز ممکن نبود** — شرط «از قبل تصمیم گرفته» روی `not_requested/awaiting_approval` هم صادق بود ← اصلاح شد.
3. **SQL نامعتبر در دید کلاینت** — نبود فاصله قبل از `AND` پارامتر `:idAND` می‌ساخت ← رفع.
4. **ردیف ستون تکراری در UPDATE ترنزیشن** (`updated_at` دو بار) و **فراخوانی تابع PHP ناموجود** `datetime(...)` در اسکریپت ← حذف/اصلاح.
5. **ایجاد تسک بدون مسئول در هیچ حالتی ممکن نبود** (draft مرده بود) ← ایجاد بدون انتساب مجاز؛ انتساب بعدی از طریق `assign`.
6. **دید کلاینت در `list`/`get` کاملاً بسته بود** + احتمال نشت نظرات داخلی ← شاخهٔ اختصاصی کلاینت با فیلتر نظرات/فایل‌ها/دریافت‌کنندگان و پنهان‌سازی activity.
7. **تغییر حالت به single با چند عضو** مجاز بود ← قید 422 اضافه شد.
