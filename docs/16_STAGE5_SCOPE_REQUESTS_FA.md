# درخواست‌های مرحله ۵ — حساب پول + آمار/اسکور کارمندان

**تاریخ ثبت:** ۹ اکتبر ۲۰۲۶  
**وضعیت:** دامنه پیشنهادی مرحله ۵ — منتظر تأیید و تکمیل یک بند ناتمام کاربر  
**قید سرتاسری کاربر:** برای همه محاسباتی که به آن می‌خورد، از **موتور پیش‌بینی Earned Value** همین سیستم استفاده شود؛ هر گزینه به هر تعداد ستون/جدول دیتابیس که نیاز داشته باشد، محاسبات لازم داشته باشد.

## الف) حساب پول — فقط دسترسی ادمین

| # | درخواست | برداشت طراحی (پیش‌نویس) |
|---|---|---|
| ۱ | دسترسی فقط پیش ادمین‌ها | مسیر API جدا با `requireAdminJson`؛ کارمند/کلاینت → 403 حتی با direct request |
| ۲ | مبلغی که کلاینت در برابر هر پروژه پرداخت کرده | ثبت پرداخت‌ها per project (تاریخ، مبلغ، یادداشت) — «درآمد» |
| ۳ | تمام مصارف یک پروژه | ثبت مصارف per project (دسته، مبلغ، توضیح، تاریخ) |
| ۴ | برداشت‌ها باید ذکر شوند | ثبت برداشت‌ها (چه کسی، چقدر، چه وقت، بابت چه) |
| ۵ | سهم شرکا معلوم باشد | **شرکا = ادمین‌های فول‌اکسس** (تعدادشان قابل شمارش از جدول ادمین‌ها)؛ سهم هر شرکت محاسبه و نمایش داده شود |

**محاسبات پایه:** درآمد − مصارف = سود خام؛ سود − برداشت‌ها = باقیمانده؛ سهم هر شرکت از باقیمانده (تقسیم مساوی، مگر سازوکار سهم‌دهی دیگری تأیید شود).  
**اتصال EVM:** هزینه‌های ثبت‌شده هر پروژه = **AC واقعی** → با همان فرمول‌های مرحله ۴، `CPI/EAC` زنده می‌شود؛ پرداخت‌های کلاینت در برابر `PV/EV` قابل مقایسه‌اند (گزارش «پول در برابر ارزش کسب‌شده»).

## ب) حالت کارمندان — فقط برای ادمین‌ها

| # | درخواست | برداشت طراحی (پیش‌نویس) |
|---|---|---|
| ۱ | هر کارمند کارهایش دیده شود: چه کارهایی، چقدر، چقدر کیفیت؟ | صفحه آمار: فهرست کارهای تکمیل‌شده/تأییدشده هر کارمند (تاریخ، پروژه، تسک، امتیاز) |
| ۲ | ارزش هر کار فرق دارد (اسکور متناسب با تأثیر کار بر فیصدی پروژه) | هنگام **تأیید ادمین**، افزایشِ درصد پروژه که همان کار ایجاد کرد = امتیاز آن کار؛ مثلاً آیتمی با وزن ۲۰٪ که از ۰ به ۱۰۰ رفت → سهمش در overall را همان لحظه به عنوان امتیاز ثبت کنیم |
| ۳ | امتیاز به‌خاطر تشویق کارمند | انباشت امتیاز هر کارمند (تجمعی + تفکیکی) |
| ۴ | **نمایش کارمند: فقط یک عدد خالی، بدون هیچ نوشته‌ای کنار/بغلش** — کارمند نباید بفهمد مربوط چیست | در پروفایل/داشبورد کارمند یک عدد بدون برچسب؛ هیچ توضیح، آیکون یا عنوانی. بعداً خودتان برایشان توضیح می‌دهید |
| ۵ | **صفحه ادمین → قسمت «کارمندان»**: کلیک → آمار همه نمایان شود | بخش/دکمه «کارمندان» در CPM فقط برای ادمین؛ کلیک → جدول آمار کامل هر کارمند |
| ۶ | + آمار پیشرفت پروژه‌ها هم همان‌جا | همان پنل، تب/بخش دوم: روند پیشرفت پروژه‌ها (درصد + منحنی) |

**منطق نمره (پیش‌نویس برای تأیید):**  
`امتیاز کار = Δ(درصد کل پروژه پس از تأیید ادمین)` — همان عددی که در صفحه پروژه‌ها بالا رفت. چند مسئولِ مشترک → تقسیم مساوی. تسکِ بدون تأیید/لغوشده → صفر. امتیاز در جدول رویداد (task, employee, points, timestamp) ثبت می‌شود تا هم قابل حساب باشد هم قابل بازبینی.

**اتصال EVM:** آمار پیشرفت پروژه‌ها در پنل ادمین از همان موتور `progress_api` (درصد، planned، SPI، پیش‌بینی، S-curve) استفاده می‌کند — بدون محاسبه موازی.

## ضمیمه الف — تکمیل درخواست‌های کاربر (۹ اکتوبر ۲۰۲۶)

### ۱) راپورها (Reports) — گزینه جدید در منوی ادمین
- دکمه **📊 Reports** در نوار ابزار ادمین → مودال تمام‌صفحه با فیلتر:
  `From / To (تاریخ)` + `پروژه` + **Generate** + **🖨 Print**.
- راپور از **همه چیز دیتابیس** گزارش می‌گیرد:
  - خلاصه (پروژه‌ها، میانگین پیشرفت، کارها، درآمد/مصرف/برداشت/باقیمانده/سهم شرکا)
  - پیشرفت پروژه‌ها + ستون‌های EVM (برنامه امروز، SPI، پیش‌بینی ختم، لغزش روز)
  - سری اسنپ‌شات‌های پیشرفت (تاریخ به تاریخ)
  - کارها: به تفکیک وضعیت، به تفکیک کارمند (تکمیل‌شده)، و فهرست کامل با مسئول/تاریخ
  - مالی: پرداخت‌ها + مصارف (با دسته) + برداشت‌ها + جمع‌ها + سهم هر شرکت
  - جدول امتیاز کارمندان (رتبه‌بندی)
- **پرینت**: دکمه Print → خروجی تمیز `@media print` فقط از ناحیه راپور (بدون منوها/دکمه‌ها).
- فیلتر تاریخ با اعتبارسنجی YYYY-MM-DD (تاریخ خراب → 422).
- فقط ادمین (`requireAdminJson`) — کارمند → 403.

### ۲) نیک (NiK) — چت‌بات حافظه‌دار
- دکمه شناور �رو پنل گفتگو روی **هر دو پوسته** (CPM + Tasks).
- **حافظه کامل سیستم**: هر سؤال با داده زنده DB/EVM ترکیب می‌شود —
  پیشرفت/برنامه/SPI/پیش‌بینی هر پروژه، کارهای باز کاربر، کارهای عقب‌مانده،
  جدول امتیازها، آمار کارمندان، خلاصه مالی (درآمد/مصرف/برداشت/سهم شرکا)، تاریخ.
- **فهم عامیانه**: فارسی/دری، پشتو و انگلیسی؛ اسامی پروژه‌ها و افراد از متن سؤال
  شناسایی می‌شوند؛ «همو پروژه» = آخرین پروژه ذخیره‌شده در حافظه دنبال‌کننده.
- **حافظه شخصی**: «به خاطر بسپار: …» / «چه یادته؟» (جدول `nik_memory`).
- **گفتار**: دکمه 🔊 بلندخوانی آخرین جواب با Web Speech API مرورگر (fa-IR/en-US).
- **امنیت**: فقط کاربران واردشده؛ CSRF روی POST؛ مالی و رتبه‌بندی فقط ادمین؛
  هر مکالمه در `nik_messages` ذخیره می‌شود؛ سؤال‌های بی‌پاسخ برای یادگیری آینده.
- **زبان برنامه‌نویسی**: PHP نگه داشته شد — موتور قطعی کلیدواژه/نیت (`nik_engine.php`)
  پاسخ را از دیتابیس می‌سازد (بدون وابستگی به اینترنت)، گفتار از طریق
  Web Speech API مرورگر. دلیل: قطعیت + امنیت + بدون هزینه API؛ LLM بعداً
  می‌تواند روی همین پوسته `intent/answer/suggestions` سوار شود (مستندات ۰۹ §تدوین).

### ۳) کارت امتیاز کارمند (تکمیل قاعده)
- در بخش آمار صفحه کارها یک کارت **بدون عنوان** فقط با یک عدد (امتیاز خالص)
  برای بیننده؛ کنارش هیچ نوشته‌ای نیست.
